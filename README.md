# 微信聊天 OCR 自动归档

这是一个面向 macOS 微信一对一聊天的本地归档工具。程序可按选择的方向自动滚动聊天窗口、连续截屏并调用 macOS Vision OCR，将屏幕上可见的文字聊天保存为可核对、可修正和可导出的本地档案。

项目不读取、注入或破解微信数据库，不调用云端 OCR，聊天内容不会由程序上传。请只处理本人有权查看和归档的聊天。

当前版本仅支持 macOS，本轮不包含 Windows 适配。

## 技术方案

| 功能 | 技术 | 说明 |
| --- | --- | --- |
| 桌面界面 | Python 3.12、PySide6 | 独立采集/查看页面、联系人与消息筛选、分页和截图核对 |
| 窗口识别 | PyObjC、Quartz | 读取窗口编号、进程、标题和窗口尺寸 |
| 前台应用控制 | PyObjC、Cocoa | 激活微信并确认滚动目标仍是微信 |
| 自动滚动 | Quartz `CGEvent` | 根据采集方向发送正/负像素滚轮事件，不修改微信进程 |
| 窗口截图 | macOS `screencapture` | 按窗口编号截取，不采集整个桌面 |
| 稳定检测 | Pillow | 缩小灰度图后计算平均像素差 |
| OCR | Swift、Vision | Python 自动编译并调用本地辅助程序 |
| 图片文字过滤 | NumPy、SciPy | 验证气泡颜色、连通区域尺寸和填充率 |
| 消息解析 | Python、正则表达式 | 判断发送方、时间和系统消息 |
| 日期解析 | Python `datetime`、`zoneinfo` | 解析相对时间，统一为时间正序后仅向后填补日期 |
| 模糊去重 | RapidFuzz | 匹配相邻页面的最长重叠消息序列 |
| 数据库 | Python `sqlite3` | 保存当前值、OCR 原文、软删除和 JSON 修订快照，并执行筛选与分页 |
| 多格式导出 | `json`、Jinja2、openpyxl | 按所选字段生成 JSON、Markdown、HTML 和 Excel，不复制截图 |
| 测试 | pytest | 覆盖滚动状态、区域、解析、去重和存储 |

PyObjC 的 Vision 请求在当前 macOS 26/Python 环境下返回异常状态，因此 OCR 使用一个很小的 Swift 原生辅助组件。所有流程仍由 Python 管理，辅助组件只接收本地图片路径并输出带坐标和置信度的 JSON。

## 自动滚动流程

程序支持两种方向：停在最新消息处向上读取，或停在最早消息处向下读取。采集步骤相同，滚轮事件方向相反：

1. 激活用户选中的微信窗口。
2. 按校准后的归一化坐标截取聊天区域第一页。
3. 确认当前前台应用仍是目标微信进程。
4. 按所选方向将滚轮事件投递到聊天区域中心。
5. 每隔约 180 毫秒截取一次区域低分辨率图。
6. 连续两次像素差低于阈值后认为页面稳定。
7. 与上一页比较，内容变化时保存为新页。
8. 连续三次没有明显变化时认为已经到达顶部或底部。
9. 达到最大页数、微信失焦、用户停止或按 Esc 时结束。

滚动距离默认 650 像素，使相邻页面保留一部分重叠内容。重叠是防止消息漏采和恢复页面顺序所必需的，不能设置为完整页面高度。

校准对话框会实时显示聊天选区的截图像素尺寸，并按照选区高度的 60%～75% 给出建议滚动范围。确认后该尺寸和建议值也会保留在主窗口。Retina 截图像素与系统滚动事件的体感距离可能存在差异，建议值用于初始配置，仍应通过第一页重叠量校正。

## OCR 与消息重建

Vision 返回文字、置信度和归一化边界框。第一版按以下规则处理：

- OCR 结果周围必须存在微信绿色或浅灰文字气泡表面。
- 通过色块连通区域的尺寸和填充率排除图片、网页截图和分享卡片。
- 文字中心位于右半区时标记为“我”。
- 文字中心位于左半区时标记为用户配置的对方称呼。
- 居中且符合日期、时间或系统通知格式时标记为“系统”。
- 同侧、垂直距离很小且起始位置接近的文字行合并为一条消息。
- 可见时间会关联到其后的消息，但不会为没有显示时间的内容虚构精确时间。

日期时间标准化规则：

- 仅显示 `12:30` 时，使用任务开始当天的日期。
- `Yesterday 12:30`、OCR 常见误差 `Yesterdat 12:30` 和 `昨天 12:30` 使用前一天日期。
- `Today`、`前天`、中英文星期、`7月29日` 和 `2026-07-29` 均转换为实际日期。
- `上午/下午/晚上/凌晨` 和 `AM/PM` 转换为 24 小时制。
- 标准结果写入 `occurred_at`，采用带本地时区的 ISO 8601 格式，例如 `2026-07-29T20:15+08:00`。
- 原始微信标签继续保存在 `visible_time`，用于和截图核对。
- 向上采集得到的新页会反转为时间正序；向下采集保持原顺序。
- 只有日期空白时才继承时间正序中上一条已知日期，写入 `occurred_date` 并标记 `date_source=inherited`。
- 继承日期不会生成不存在的精确时间；档案开头没有日期锚点时保持空白并标记为待补。
- 手工修改日期后标记 `date_source=manual`。

相邻截图按“发送方 + 标准化文本”进行模糊序列匹配。页面内允许一个短消息形成重叠；跨运行增量合并则要求更强证据，避免把两次真实出现的“好”等短消息误删。

旧版本已经写入 SQLite 的记录不会被直接删除。升级后，程序在后台逐张复核来源截图，并将文字可见状态写回 SQLite；每次只分析一张图，界面不会因为整理旧档案而阻塞。为避免两个任务同时写数据库，首次整理期间采集按钮会暂时禁用并在完成后自动恢复。未通过的图片文字不会出现在界面和新导出中，截图缺失时则保留消息供人工核对。整理只需执行一次，后续启动、搜索和切换联系人直接使用已保存的结果。

## 数据库设计

SQLite 文件包含四张表：

- `chats`：聊天对象和建档时间。
- `sessions`：每次自动采集任务、页数和截图目录。
- `messages`：顺序、当前文字、OCR 原文、发送方、日期来源、置信度、位置、来源截图、可见与软删除状态。
- `message_revisions`：每次修改、删除和恢复操作前后的 JSON 快照与操作时间。
- SQLite 使用 WAL 日志模式，消息按聊天和全局顺序建立索引。

查看页的联系人计数、发送方筛选、正文搜索和分页共用 `is_visible` 状态。列表每次最多从 SQLite 读取 200 条消息，不会为了显示第一页把整个联系人档案载入内存。旧数据库首次升级时，待复核记录会暂时不计入可见数量；后台整理完成后列表会自动刷新。

聊天数据、截图和导出文件全部位于界面选择的归档目录。新会话的截图目录以相对路径写入数据库；打开旧库时，只把位于当前归档根目录内的旧绝对路径转换为相对路径，不移动或删除文件。默认的项目 `data/` 目录已加入 `.gitignore`，不会提交到 Git 仓库。

## 使用流程

1. 在顶部选择归档目录；迁移电脑时选择包含数据库和 `captures/` 的原目录。
2. 打开微信和需要归档的聊天，根据采集方向停留在最新或最早消息处。
3. 启动工具并完成 macOS 权限授权。
4. 点击“刷新”，选择目标微信窗口。
5. 点击“校准区域”，只框选消息滚动区域，排除会话列表、标题栏和输入框。
6. 选择采集方向，并根据界面显示的区域尺寸和建议范围设置滚动距离。
7. 点击“开始记录”，采集期间不要操作微信或切换窗口。
8. 完成后切换到“查看聊天记录”，选择联系人并搜索文字记录。
9. 点击任意文字记录，在右侧原始截图中核对高亮位置；识别不准时使用“修改”或“删除”。
10. 使用顶部“导出”选择全部可见记录、当前筛选结果或表格中多选的记录，再选择格式和字段。
11. 右键联系人可直接导出该联系人的全部可见记录，不受消息搜索、发送人筛选和分页影响。
12. 右键聊天记录可修改、删除/恢复、查看截图，以及导出当前或多选记录。

## 安全设计

- 每次发送滚动前确认前台应用仍为微信。
- 微信失焦后立即停止，不向其他应用继续发送滚动事件。
- 最大页数防止无限循环。
- 连续无变化阈值防止在顶部反复滚动。
- 暂停、停止和 Esc 三种中断方式。
- OCR 和导出均在本机完成。
- `data/`、`.build/` 和缓存目录均不进入 Git。

## 第一版限制

- 发送方主要依据文字位置判断，超长气泡可能需要人工复核。
- 图片、语音、视频、引用卡片和复杂表情会被忽略，不进入文字档案。
- 只有微信实际显示时间标签的消息段才能获得可靠时间；同一标签后的消息共享该可见时间。
- 微信主题、缩放比例和界面更新可能影响识别区域与准确率。
- 自动滚动只能读取微信当前能够加载和显示的历史记录。
- 若新一轮扫描与旧档案没有重叠消息，无法严格证明两批记录的连接位置。
- 联系人档案目前以手动输入的“对方称呼”区分；相同称呼会归入同一个档案。
- 当前 `run.command` 包含本机绝对路径，正式分发前需要改成可移植启动器。
