# 微信聊天 OCR 自动归档

这是一个面向 macOS 微信一对一聊天的本地归档工具。程序自动向上滚动聊天窗口、连续截屏并调用 macOS Vision OCR，将屏幕上可见的聊天内容保存为可搜索的 HTML、Markdown、JSON 和 SQLite 档案。

项目不读取、注入或破解微信数据库，不调用云端 OCR，聊天内容不会由程序上传。请只处理本人有权查看和归档的聊天。

## 当前进展

第一版已完成：

- PySide6 桌面界面和微信窗口选择
- 辅助功能、屏幕录制权限检查
- 聊天内容区域可视化框选与归一化坐标保存
- Quartz 像素级自动向上滚动
- 滚动后画面稳定检测、到顶判断和最大页数保护
- 微信失去焦点安全停止、暂停/继续、Esc 紧急停止
- macOS Vision 本地中英文 OCR
- 只保留微信文字气泡，忽略图片和分享卡片内部文字
- 左右发送方判断、系统时间识别、多行文本合并
- 相邻截图重叠去重和跨运行增量保存
- SQLite、HTML、Markdown、JSON 输出
- 不操作真实微信的核心自动化测试

已验证 Conda 环境、GUI 启动、Vision 中文 OCR 和核心数据流程。真实长聊天的自动滚动参数、复杂气泡识别和异常恢复仍需在更多微信界面状态下持续验证。

## 技术方案

| 功能 | 技术 | 说明 |
| --- | --- | --- |
| 桌面界面 | Python 3.12、PySide6 | 窗口选择、校准、控制、预览和结果表格 |
| 窗口识别 | PyObjC、Quartz | 读取窗口编号、进程、标题和窗口尺寸 |
| 前台应用控制 | PyObjC、Cocoa | 激活微信并确认滚动目标仍是微信 |
| 自动滚动 | Quartz `CGEvent` | 发送系统级像素滚轮事件，不修改微信进程 |
| 窗口截图 | macOS `screencapture` | 按窗口编号截取，不采集整个桌面 |
| 稳定检测 | Pillow | 缩小灰度图后计算平均像素差 |
| OCR | Swift、Vision | Python 自动编译并调用本地辅助程序 |
| 图片文字过滤 | NumPy、SciPy | 验证气泡颜色、连通区域尺寸和填充率 |
| 消息解析 | Python、正则表达式 | 判断发送方、时间和系统消息 |
| 模糊去重 | RapidFuzz | 匹配相邻页面的最长重叠消息序列 |
| 数据库 | Python `sqlite3` | 保存会话、采集任务和增量消息 |
| HTML 导出 | Jinja2 | 生成可搜索、可直接浏览的聊天页面 |
| 测试 | pytest | 覆盖滚动状态、区域、解析、去重和存储 |

PyObjC 的 Vision 请求在当前 macOS 26/Python 环境下返回异常状态，因此 OCR 使用一个很小的 Swift 原生辅助组件。所有流程仍由 Python 管理，辅助组件只接收本地图片路径并输出带坐标和置信度的 JSON。

## 自动滚动流程

程序从当前聊天的最新位置开始向上读取：

1. 激活用户选中的微信窗口。
2. 按校准后的归一化坐标截取聊天区域第一页。
3. 确认当前前台应用仍是目标微信进程。
4. 将滚轮事件投递到聊天区域中心。
5. 每隔约 180 毫秒截取一次区域低分辨率图。
6. 连续两次像素差低于阈值后认为页面稳定。
7. 与上一页比较，内容变化时保存为新页。
8. 连续三次没有明显变化时认为已经到顶。
9. 达到最大页数、微信失焦、用户停止或按 Esc 时结束。

滚动距离默认 650 像素，使相邻页面保留一部分重叠内容。重叠是防止消息漏采和恢复页面顺序所必需的，不能设置为完整页面高度。

## OCR 与消息重建

Vision 返回文字、置信度和归一化边界框。第一版按以下规则处理：

- OCR 结果周围必须存在微信绿色或浅灰文字气泡表面。
- 通过色块连通区域的尺寸和填充率排除图片、网页截图和分享卡片。
- 文字中心位于右半区时标记为“我”。
- 文字中心位于左半区时标记为用户配置的对方称呼。
- 居中且符合日期、时间或系统通知格式时标记为“系统”。
- 同侧、垂直距离很小且起始位置接近的文字行合并为一条消息。
- 可见时间会关联到其后的消息，但不会为没有显示时间的内容虚构精确时间。

相邻截图按“发送方 + 标准化文本”进行模糊序列匹配。页面内允许一个短消息形成重叠；跨运行增量合并则要求更强证据，避免把两次真实出现的“好”等短消息误删。

## 数据库设计

SQLite 文件包含四张表：

- `chats`：聊天对象和建档时间。
- `sessions`：每次自动采集任务、页数和截图目录。
- `messages`：顺序、发送方、文字、置信度、位置、可见时间和来源截图。
- SQLite 使用 WAL 日志模式，消息按聊天和全局顺序建立索引。

聊天数据、截图和导出文件全部位于 `data/`，该目录已加入 `.gitignore`，不会提交到 Git 仓库。

## macOS 权限

程序需要：

- “辅助功能”：激活微信、定位滚动区域和发送滚动事件。
- “屏幕与系统音频录制”：按窗口编号截取微信内容。

首次启动后点击“检查权限”，在“系统设置 -> 隐私与安全性”中允许当前终端或应用。macOS 可能要求重新启动 Python、终端或工具才能应用权限。

## 使用流程

1. 打开微信和需要归档的聊天，停留在最新消息处。
2. 启动工具并完成 macOS 权限授权。
3. 点击“刷新”，选择目标微信窗口。
4. 点击“校准区域”，只框选消息滚动区域，排除会话列表、标题栏和输入框。
5. 设置对方称呼、最多页数和滚动距离。
6. 点击“开始记录”，采集期间不要操作微信或切换窗口。
7. 完成后在界面查看识别结果或打开 HTML 导出。

## 安全设计

- 每次发送滚动前确认前台应用仍为微信。
- 微信失焦后立即停止，不向其他应用继续发送滚动事件。
- 最大页数防止无限循环。
- 连续无变化阈值防止在顶部反复滚动。
- 暂停、停止和 Esc 三种中断方式。
- OCR 和导出均在本机完成。
- `data/`、`.build/` 和缓存目录均不进入 Git。

## 第一版限制

- 发送方主要依据文字位置判断，超长气泡可能需要人工复核。
- 图片、语音、视频、引用卡片和复杂表情会被忽略，不进入文字档案。
- 微信没有显示的精确发送时间无法通过 OCR 得到。
- 微信主题、缩放比例和界面更新可能影响识别区域与准确率。
- 自动滚动只能读取微信当前能够加载和显示的历史记录。
- 若新一轮扫描与旧档案没有重叠消息，无法严格证明两批记录的连接位置。
- 当前 `run.command` 包含本机绝对路径，正式分发前需要改成可移植启动器。
