# 微信聊天 OCR 自动归档

这是一个面向 macOS 微信一对一聊天的本地归档工具。程序可按选择的方向自动滚动聊天窗口、连续截屏并调用 macOS Vision OCR，将屏幕上可见的文字与语音消息占位符保存为可核对、可修正和可导出的本地档案。

项目不读取、注入或破解微信数据库，不调用云端 OCR，聊天内容不会由程序上传。请只处理本人有权查看和归档的聊天。

当前版本仅支持 macOS，本轮不包含 Windows 适配。

## 自动滚动流程

程序支持两种方向：停在最新消息处向上读取，或停在最早消息处向下读取。采集步骤相同，滚轮事件方向相反：

1. 激活用户选中的微信窗口。
2. 按校准后的归一化坐标截取聊天区域第一页。
3. 确认当前前台应用仍是目标微信进程。
4. 按所选方向将滚轮事件投递到聊天区域中心。
5. 每隔约 180 毫秒截取一次区域低分辨率图。
6. 连续两次像素差低于阈值后认为页面稳定。
7. 与上一页比较，内容变化时保存为新页。
8. 连续三次没有明显变化时认为已经到达顶部或底部。
9. 达到最大页数、微信失焦、用户停止或按 Esc 时结束。

滚动距离默认 650 像素，使相邻页面保留一部分重叠内容。重叠是防止消息漏采和恢复页面顺序所必需的，不能设置为完整页面高度。

校准对话框会实时显示聊天选区的截图像素尺寸，并按照选区高度的 60%～75% 给出建议滚动范围。确认后该尺寸和建议值也会保留在主窗口。Retina 截图像素与系统滚动事件的体感距离可能存在差异，建议值用于初始配置，仍应通过第一页重叠量校正。

## OCR 与消息重建

Vision 返回文字、置信度和归一化边界框。当前版本按以下规则处理：

- OCR 结果周围必须存在微信绿色或浅灰文字气泡表面。
- 通过色块连通区域的尺寸和填充率排除图片、网页截图和分享卡片。
- 语音气泡不依赖 OCR 文字行：先扫描左右气泡组件，再结合扬声器图标和 `8"`、`9秒` 等秒数确认。
- 语音正文固定为 `[语音消息]`，秒数单独保存为 `voice_duration_seconds`；不会播放、提取或转写音频。
- 语音气泡内被误识别的 `$ 8"` 等图标噪声和秒数字符会被抑制，不再生成普通文字记录。
- 语音使用气泡截图 dHash、时长、发送人和消息类型生成内部指纹，正文相同也不会只依赖占位符去重。
- 文字中心位于右半区时标记为“我”。
- 文字中心位于左半区时标记为用户配置的对方称呼。
- 居中且符合日期、时间或系统通知格式时标记为“系统”。
- 同侧、垂直距离很小且起始位置接近的文字行合并为一条消息。
- 可见时间会关联到其后的消息，但不会为没有显示时间的内容虚构精确时间。

日期时间标准化规则：

- 仅显示 `12:30` 时，使用任务开始当天的日期。
- `Yesterday 12:30`、OCR 常见误差 `Yesterdat 12:30` 和 `昨天 12:30` 使用前一天日期。
- `Today`、`前天`、中英文星期、`7月29日` 和 `2026-07-29` 均转换为实际日期。
- `上午/下午/晚上/凌晨` 和 `AM/PM` 转换为 24 小时制。
- 标准结果写入 `occurred_at`，采用带本地时区的 ISO 8601 格式，例如 `2026-07-29T20:15+08:00`。
- 原始微信标签继续保存在 `visible_time`，用于和截图核对。
- 向上采集得到的新页会反转为时间正序；向下采集保持原顺序。
- 只有日期空白时才继承时间正序中上一条已知日期，写入 `occurred_date` 并标记 `date_source=inherited`。
- 继承日期不会生成不存在的精确时间；档案开头没有日期锚点时保持空白并标记为待补。
- 手工修改日期后标记 `date_source=manual`。

相邻截图按“发送方 + 标准化文本”进行模糊序列匹配。页面内允许一个短消息形成重叠；跨运行增量合并则要求更强证据，避免把两次真实出现的“好”等短消息误删。

## 跨次采集去重与顺序冲突

每张截图保存文件 SHA-256 和 64 位 dHash。每条消息使用首次 OCR 的原文、首次识别发送人和消息类型生成稳定 BLAKE2 指纹；用户后来修改文字或发送人时保留原指纹，因此再次扫描仍能识别原记录。数据库同时保存上一条和下一条消息指纹，用于发现可疑重复和核对相邻关系。

新一轮采集写入前会在同一联系人已有记录中寻找连续顺序锚点。两个以上连续消息可以构成强锚点；单条消息只有原文长度足够时才可作为锚点。软删除消息仍参与锚点判断，避免再次扫描后重新出现。

找不到锚点或存在多个等价锚点时，本批消息只写入 `capture_conflicts` 暂存区，不修改正式消息顺序。“待复核 -> 采集冲突”可执行：

1. 忽略本次暂存消息。
2. 作为新消息追加到联系人档案末尾。
3. 输入消息序号后插入指定位置。
4. 按建议锚点合并；执行前会根据当前档案重新校验锚点，档案已经变化或锚点仍不唯一时拒绝写入。

## 断点续扫

采集开始前先建立会话记录。每保存一张截图就立即写入页码、相对路径、SHA-256 和 dHash；每完成一页 OCR 就立即保存原始 OCR JSON。任务状态区分 `capturing`、`ocr`、`interrupted`、`failed`、`conflict`、`completed` 和 `abandoned`，错误信息会记录发生在截图、OCR 还是合并阶段。

程序重启后，“获取聊天记录”页面会列出未完成任务。继续任务时需要先把微信停留在右侧最后一张截图附近，程序临时截图并比较 dHash 与像素差，匹配后才继续滚动。已经完成 OCR 的页面直接复用数据库中的 OCR JSON，不重复识别；如果任务已经进入 OCR 或合并阶段，也不会重新截图。放弃任务只更新会话状态，已保存截图和检查点仍保留。

微信没有提供可靠的聊天滚动位置接口，因此断点恢复保存的是“最后页面锚点”，不是一个不可验证的滚动条像素值。

## 待复核与修订历史

“待复核”是独立主页面，包含“异常消息”和“采集冲突”两个子页面。异常消息按以下动态规则生成：OCR 置信度低于阈值、日期空白、文字中心接近左右分界线、疑似重复相邻关系、来源截图缺失、OCR 坐标越界、语音检测存疑或语音时长缺失。置信度阈值默认 75%，会在本机设置中记忆。

异常消息可按状态和原因筛选，并支持截图高亮核对、修改、软删除、批量确认、暂不处理和重置为待复核。修改或恢复历史版本后，该消息的复核状态会重置，以便再次确认。

聊天记录右键菜单中的“查看修订历史”显示 OCR 初始版本及每次修改、删除、恢复和版本恢复的时间与变化字段。恢复任一版本会新增一条 `revert` 修订，不覆盖或删除后续历史。普通聊天导出仍只导出当前记录，不包含修订历史。

旧版本已经写入 SQLite 的记录不会被直接删除。升级后，程序在后台逐张复核来源截图，并将文字可见状态写回 SQLite；每次只分析一张图，界面不会因为整理旧档案而阻塞。为避免两个任务同时写数据库，首次整理期间采集按钮会暂时禁用并在完成后自动恢复。未通过的图片文字不会出现在界面和新导出中，截图缺失时则保留消息供人工核对。整理只需执行一次，后续启动、搜索和切换联系人直接使用已保存的结果。

## 数据库设计

SQLite 文件包含七张主要表：

- `chats`：聊天对象和建档时间。
- `sessions`：每次自动采集任务、页数和截图目录。
- `messages`：顺序、当前文字、OCR 原文、发送方、日期来源、置信度、位置、来源截图、语音时长、语音视觉哈希、可见与软删除状态。
- `message_revisions`：每次修改、删除和恢复操作前后的 JSON 快照与操作时间。
- `capture_pages`：逐页截图路径、页面哈希、OCR 状态和原始 OCR JSON。
- `message_reviews`：人工复核状态和复核时间。
- `capture_conflicts`：无法自动确定顺序的整批消息、建议锚点和处理状态。
- SQLite 使用 WAL 日志模式，消息按聊天和全局顺序建立索引。

数据库当前 schema 版本使用 `PRAGMA user_version = 5`。有实际内容的旧数据库首次升级前，会在同一目录生成 `archive-pre-v5-日期时间.sqlite3`。备份使用 SQLite Online Backup API，可包含 WAL 中已提交的数据；只备份数据库，不递归复制可能很大的 `captures/` 截图目录。新建空库不会生成升级备份。

查看页的联系人计数、发送方筛选、正文搜索和分页共用 `is_visible` 状态。列表每次最多从 SQLite 读取 200 条消息，不会为了显示第一页把整个联系人档案载入内存。旧数据库首次升级时，待复核记录会暂时不计入可见数量；后台整理完成后列表会自动刷新。

聊天数据、截图和导出文件全部位于界面选择的归档目录。新会话的截图目录以相对路径写入数据库；打开旧库时，只把位于当前归档根目录内的旧绝对路径转换为相对路径，不移动或删除文件。默认的项目 `data/` 目录已加入 `.gitignore`，不会提交到 Git 仓库。

## 开发环境

推荐 macOS 14 及以上、Apple Silicon、Conda 和 Xcode Command Line Tools。当前开发环境使用 Python 3.12；不要直接使用 Python 3.14，以免 PySide6、PyObjC 或打包链路出现兼容问题。

从环境定义创建 Conda 环境：

```bash
conda env create -f environment.yml
```

## 使用流程

1. 在顶部选择归档目录；迁移电脑时选择包含数据库和 `captures/` 的原目录。
2. 打开微信和需要归档的聊天，根据采集方向停留在最新或最早消息处。
3. 启动工具并完成 macOS 权限授权。
4. 点击“刷新”，选择目标微信窗口。
5. 点击“校准区域”，只框选消息滚动区域，排除会话列表、标题栏和输入框。
6. 选择采集方向，并根据界面显示的区域尺寸和建议范围设置滚动距离。
7. 点击“开始记录”，采集期间不要操作微信或切换窗口。
8. 中途停止或异常退出后，在“未完成任务”中选择任务；先把微信移回最后截图附近，再点击“继续任务”。
9. 完成后切换到“查看聊天记录”，选择联系人并搜索文字记录。
10. 点击任意文字记录，在右侧原始截图中核对高亮位置；识别不准时使用“修改”或“删除”。
11. 语音记录正文显示为 `[语音消息]`，状态与截图详情显示时长；时长存疑时到“待复核”确认。
12. 右键消息选择“查看修订历史”，可比较并恢复任一历史版本。
13. 切换到“待复核”，集中确认异常消息并处理跨次采集顺序冲突。
14. 使用顶部“导出”选择全部可见记录、当前筛选结果或表格中多选的记录，再选择格式和字段；语音时长是可选字段。
15. 右键联系人可直接导出该联系人的全部可见记录，不受消息搜索、发送人筛选和当前分页影响。

## 安全设计

- 每次发送滚动前确认前台应用仍为微信。
- 微信失焦后立即停止，不向其他应用继续发送滚动事件。
- 最大页数防止无限循环。
- 连续无变化阈值防止在顶部反复滚动。
- 暂停、停止和 Esc 三种中断方式。
- OCR 和导出均在本机完成。
- `data/`、`.build/` 和缓存目录均不进入 Git。

## 当前限制

- 发送方主要依据文字位置判断，超长气泡可能需要人工复核。
- 语音只保存 `[语音消息]`、时长和截图位置，不提取或转写具体语音内容。
- 图片、视频、引用卡片和复杂表情会被忽略，不进入聊天档案。
- 只有微信实际显示时间标签的消息段才能获得可靠时间；同一标签后的消息共享该可见时间。
- 微信主题、缩放比例和界面更新可能影响识别区域与准确率。
- 自动滚动只能读取微信当前能够加载和显示的历史记录。
- 若新一轮扫描与旧档案没有可靠重叠消息，程序会暂存冲突，需要人工选择追加或插入位置。
- 联系人档案目前以手动输入的“对方称呼”区分；相同称呼会归入同一个档案。
- 当前 `run.command` 包含本机绝对路径，正式分发前需要改成可移植启动器。
